# OOO 敏感資料遮罩 v0.8.2

Chrome Manifest V3 外掛。全程在本機用規則處理，不呼叫 AI、雲端 API 或任何外部服務。不代表完成正式去識別化。

## 舊版如何升級

1. 將此 ZIP 解壓縮至新資料夾。
2. 如原本已安裝舊版，把新資料夾「裡面的檔案」複製到原本載入外掛的資料夾，覆蓋同名檔案；請包含新增的 settings.js、namedata.js 與 icons/ 資料夾。
3. 到 chrome://extensions，在「OOO 敏感資料遮罩」卡片按重新載入。
4. 確認詳細資料顯示版本 0.8.2，再重新整理目標網頁。
5. 不要同時啟用兩份 OOO 外掛，避免互相處理文字。

第一次安裝：chrome://extensions → 開啟開發人員模式 → 載入未封裝項目 → 選裡面直接看得到 manifest.json 的資料夾。
本機 demo.html：先到外掛詳細資料開啟「允許存取檔案網址」。

從 v0.2 或更舊版升級至 v0.3 系列時，預設辨識模式調整為「加強」，保留其他開關與已停用網站。v0.3.0 升級至 v0.3.1 會保留你已選擇的模式。

## v0.8.2 變更

- **修正常用詞被當成姓名**。「姓氏＋一個字」的雙字詞在獨立成行、冒號前、或緊接在職稱後面時，會被誤判成雙字姓名，例如「經歷：」「醫師國考」「ACLS 高級急救證照」。以履歷、自傳、臨床、行政與一般用語約 770 個詞實測引擎，找出約 320 個會誤遮的詞，人工排除可能是人名者後，將 302 個加入排除詞表（namedata.js 的 probedWords）。
- 同時是人名的詞刻意不加入（例如康健、華麗、姚明、萬芳），避免漏遮真實姓名；單獨出現的雙字姓名（王宏、林森）仍照舊遮住。
- 從這一版起，外掛與「OOO 文件去識別化」網站在同一個 repo 維護，共用同一份辨識引擎（core/）。

## v0.8.1 變更

- **修正日期規則的預設過於保守**。v0.8.0 預設只遮生日標籤附近的日期，但實務上出生日期常常沒有任何標籤，就直接放在姓名與病歷號旁邊，因此像 `1959-12-27` 這種裸日期不會被遮。
- 新增並改為預設的 `unlabelled` 模式：遮住沒有標明用途的日期，但保留標明用途的日期。判斷依據是六十餘個臨床與行政日期標籤 —— 檢驗、採檢、報告、入院、出院、手術、麻醉、回診、門診、掛號、預約、給藥、開立、處方、領藥、注射、接種、影像、切片、培養、建立、更新、列印、簽章、到期、下次、上次等，含英文對應詞，並支援表格欄首對位。
- 生日標籤或生日欄位在任何模式下都會遮，且優先於臨床標籤。
- 三種模式：`unlabelled`（預設）、`labelled`（只遮生日標籤附近，最保守）、`all`（所有近 115 年日期）。
- 病歷號的測試改為在關閉日期規則的情況下執行，兩條規則會讀到同一串數字，分開測試才看得出各自的行為。

## v0.8.0 變更

- **新增出生日期規則**（預設開啟）。出生日期是常見的個人識別資料，單靠姓名遮蔽並不足夠。
- 支援的寫法：`1986/03/02`、`1986-03-02`、`1986.03.02`、`19860302`、`1986年3月2日`、`西元1986年3月2日`、`民國75年3月2日`、`75/03/02`、`75.03.02`、`750302`、`115-03-02`、`1150302`、`03/02/1986`、`2/3/1986` 等。分隔符號 `/ . -` 與無分隔皆可，西元與民國皆可，年月日順序不限。
- 只認**最近 115 年內、真實存在**的日期。未來日期一律排除（沒有人在未來出生，這也順帶保住預約與排程日期），`1986/02/30`、`20260230` 這類不存在的日期也不算。
- 預設行為請見 v0.8.1 變更；此版原本的 `labelled` 預設過於保守，已改為 `unlabelled`。
- 為了避免誤判，版本號、IP 位址、血壓值、比例等不會被當成日期：沒有 3–4 位數年份、沒有年月日字樣、也沒有民國／西元字樣時，三個組成部分必須都是兩位數零填補才算日期（`1.2.3`、`2.10.15`、`192.168.1.1`、`120/80`、`16/9`、`10.5.20` 皆保留）。
- 表格欄首與欄位標籤的偵測機制從姓名推廣到日期，兩者共用同一套欄位對位邏輯。`<input type="date">` 一律視為生日欄位。
- 與病歷號規則的關係：v0.6.1 的「近期日期排除」讓近期日期不被當成病歷號，此版的日期規則則在有生日標籤或切到全部模式時主動遮住日期。兩者方向不同但不衝突。

- **新增「也遮住輸入框內的文字」開關**（預設開啟）：關閉後自己打字不受影響，但複製與貼上的遮罩仍然運作。

- 可在面板的「病歷號格式」中關閉。

- 預設改為加強模式，不再以有限的常見名字用字表限制預設模式。
- 補充介面詞與部門詞排除：時間、資訊、招募中、標籤、海宣部，以及資料庫、管理員、行政組等延伸詞。

- 新增本頁保留詞：外掛面板可自行排除新的誤判詞，至少兩字。一行一詞，套用會取代舊名單。名單只存在目前文件記憶體，重新整理即清除。
- 新增同頁簡稱遮罩：先找完整姓名，再取去姓後的名字，搭配文字邊界與人物上下文辨識。此功能可單獨關閉。
- 加強模式會採納經排除規則篩選後的完整姓名候選，並不表示已確認真的是人名；猜錯仍可能傳播到相同姓名及簡稱。平衡模式則只從明確欄位／人物上下文與手動名單建立簡稱。
- 單字簡稱需更明確人物語境。例如先有假姓名「王宏」後，「宏回覆」可遮，「宏觀作品」「宏偉」保留；單獨的「宏」不自動遮。手動輸入單字則會強制遮所有相同字，請慎用。
- 從原始完整姓名做兩遍處理，不从遮罩結果學習；同頁的簡稱即使以姓氏開頭，也不拿來連鎖推導更短簡稱，除非它被獨立標為另一個完整姓名。
- 若目前文件從未出現完整姓名，只靠孤立名字仍無法可靠判斷，可在本頁手動名單直接填簡稱。原住民族傳統名、外文名不自動拆成漢字簡稱。

## 姓名辨識用了哪些資料

- 姓氏：內政部 112 年姓氏排名與人數（2023-06-30 基準），官方資料集 https://data.gov.tw/dataset/126774 。剔除彙總項「其他」（排名 147）與私用區造字（排名 458）後，前 500 名有 498 個可用姓氏；面板可改為只用前 100。
- 支援字形差異（温／溫、黃／黄、高／髙）與複姓（歐陽、范姜、張簡），並支援 Unicode 延伸漢字如 𡍼。
- 常見名字：namedata.js 整理自內政部《全國姓名統計分析》107 及 112 年版的前十大常見名字與各出生年代前三大名字、內政部戶政司世代取名分析、中央健康保險署 2014 年兒少常見名排行、臺北市民政局 2013-2015 新生兒命名統計。檔案開頭列出每一份來源。
- 只有兩字名字進入「強證據」名單；單字太容易誤判，只當作軟性提示。
- 名字沒有出現在表中不代表遮不到；姓氏、欄位標籤、人物稱謂、前後文邊界等規則仍會運作。
- 排除詞：手工整理的一般詞、部門詞與臨床行政用詞，用來抑制猜測。不是官方資料，也不完整。
- 這是頻率表與規則比對，不是 NER 模型，也沒有做過真實網站準確率評估。

## 病歷號規則

- 目標格式：連續 6 至 8 碼純數字，前後不接其他數字。
- 8 碼：最後一碼為檢查碼，＝（前七碼分別乘 7、6、5、4、3、2、1 之和）mod 10。不符者不遮，這是與 8 碼日期的區分方式。
- 近期日期排除（預設開啟）：讀起來是過去半年至未來一個月之間的真實日期，就不當成病歷號。這補上了檢查碼擋不住的部分 —— 隨機 8 碼日期約有十分之一會剛好符合檢查碼，而實務上會出現在病歷畫面的日期絕大多數都落在這個區間。支援 20260707、1150707、260707 三種寫法，不存在的日期（20260230）不算數。
- 半年以外的舊日期若剛好符合檢查碼，仍會被遮住；這是保守方向的誤遮，不是漏遮。
- 代價是：若真有一個 8 碼病歷號剛好等於近期某一天的日期寫法，會漏遮。符合條件的號碼一年不到 220 個，可用本頁手動名單補上。
- 可自訂格式：面板選「自訂格式」後，一行一種樣板，`#` 代表數字、`A` 代表英文字母、`*` 兩者皆可，其餘字元照字面比對（例如 `A#######`、`##-######`）。可再勾選是否同時保留預設格式。格式長度限 4 到 32 字元，最多 20 種；無效樣板會被忽略。
- 6 至 7 碼沒有檢查碼，凡符合長度即遮。這會連帶遮住同長度的驗證碼、單號、金額、民國日期（例如 1140203）。若這類誤遮影響作業，請在面板改成「只遮 8 碼且通過檢查碼」。
- 不會切開更長的數字串：9 碼以上、身分證號的數字部分、10 碼手機號碼都不套用此規則。小數與千分位數字（12.345678、1,234,567）也排除。
- 此規則與姓名、身分證號各自獨立開關。

## 網頁處理與複製

- 在同一文字區塊內合併文字節點判斷，再把遮罩分配回原節點，可處理拆在 span/b 等標籤中的名字。
- 支援一般 th 欄首的姓名表格以及標籤／值相鄰的表格。合併欄列、ARIA 虛擬表格及特殊布局仍須依網站調整。
- 姓名發現後再做第二次同頁掃描，所以名字早於姓名欄位出現也能沿用。
- 新增或更新的文字會觸發重掃；開放式 Shadow DOM 會掃描。
- input/textarea 不改寫真正的 value；用覆蓋層顯示去識別後的欄位文字。自動 value 更新由可見頁面的一秒輪詢捕捉，可能有顯示空窗。
- 表單若只複製辨識到的人名／身分證的一部分，該敏感片段仍替換為 OOO；選取範圍內的標記與其他文字保留。contenteditable 仍採原本較保守的整次選取替換方式。
- 複製事件清除 HTML 剪貼簿格式，只輸出去識別後的純文字；可能影響富文字與表格排版。
- 貼上保護：貼上時取剪貼簿的純文字，套用同一套規則後插入。這是攔截「從 Chrome 內建 PDF 檢視器複製的內容」的實際位置，因為該檢視器是瀏覽器內部外掛，不會對網頁送出 copy 事件，外掛無法在複製當下處理。
- 貼上處理只保護「貼進 Chrome 網頁」的方向。若把 PDF 的文字貼到記事本、Word、Excel 或其他應用程式，外掛完全無法介入，內容仍是原文。
- 貼上時的姓名判斷以貼上文字本身加上目前頁面的名單為準；來源 PDF 的其他頁面內容不在判斷範圍。
- 插入方式優先使用 execCommand('insertText')，以維持網頁框架（如 React）的狀態同步；少數自訂編輯器仍可能不接受。
- 提示只表示「已套用規則」，不是「資料已安全」。
- 本頁名單在每個可注入框架分別存在，不會跨來源自動分享姓名；新載入的 iframe 需重新套用手動名單。主面板數量只反映主框架。

## 必須知道的限制

1. 原始資料仍存在原網站、JavaScript 狀態、DOM 屬性、表單值、網路流量及瀏覽器記憶體中。這不是加密或永久刪除。
2. document_idle 載入、動態更新、表單輪詢都有短暫顯示原文的可能，不能當成零閃現的螢幕分享保護。
3. 圖片、掃描 PDF、Canvas、封閉式 Shadow DOM、Chrome 特殊頁面等不保證支援。contenteditable 不做畫面遮罩，但複製事件仍嘗試處理。
3-1. Chrome 內建 PDF 檢視器：畫面上的 PDF 內容不會被遮罩，複製當下也攔不到。保護點在貼上端，且僅限貼進 Chrome 網頁時。螢幕分享、截圖、列印、貼到其他應用程式都不在保護範圍。
3-2. 病歷號規則是格式與檢查碼判斷，不是查核真實號碼；符合格式的非病歷號數字會被誤遮，格式不符的病歷號會漏遮。
4. 不辨識未顯示的 title、aria-label、data-* 等所有屬性。滑鼠懸浮提示仍可能顯示原文。
5. 姓氏也可能是普通詞語開頭。一般詞排除表是有限的；會同時有誤遮與漏遮。原住民族傳統姓名、外文姓名、罕見字、非典型字數及長句不能只靠姓氏規則可靠辨識。
6. 網站專用「複製」按鈕可能直接寫剪貼簿，不觸發 copy 事件；拖曳、下載、列印、剪下與網站自訂流程不保證受保護。程式不是防惡意網站的安全隔離層。
7. 表單覆蓋層在特殊滾動／裁切容器、彈窗等版面可能錯位；請實際核對。
8. 網頁框架可能重建文字或受到 DOM 改寫影響；若頁面異常，先停用外掛再重新整理。
8-1. 螢幕遮罩與複製貼上遮罩各自獨立。只開複製貼上遮罩時，畫面上仍看得到原文，適合自己閱讀但要避免把原文貼出去的情境；只開螢幕遮罩時，剪貼簿完全不受保護。
8-2. 常見名字表提高了句中姓名的命中率，也同時提高了把同形一般詞誤遮的機會。誤遮可用本頁保留詞排除。
8-3. 設定同步依賴 Chrome 的同步機制，資料存放於使用者自己的 Google 帳號。若不希望任何設定離開本機，可在 Chrome 的同步設定中關閉「擴充功能」項目，外掛會自動退回本機儲存。
9. 外掛維持舊版在 http/https 網站預設啟用的行為；可用面板停用個別網站，亦可由 Chrome 管理網站存取權。兩個遮罩開關等設定是全外掛共用並隨帳號同步（已停用網站清單除外），姓名、簡稱、保留詞名單則只在當前文件記憶體，不跨網站分享。
10. 對外貼出前仍需人工檢查，也需遵守所屬機構規範。請勿提供真實敏感資料來除錯。

- JavaScript 語法、manifest 結構及舊版規則測試：已通過。
- 156 項規則回歸測試：已通過，含原有平衡模式、加強預設、簡稱、詞語排除、保留詞、設定遷移、標記格式、病歷號檢查碼、近期日期排除與自訂格式，出生日期的格式、年代窗口與誤判防護，以及設定同步分流、舊版搬移與同步失效退回的測試。病歷號測試涵蓋 5 組七碼 × 全部 10 種末碼，確認只有正確檢查碼被接受。其中標記組合測試涵蓋 5 個假姓名 × 13 種前綴 × 11 種後綴，分別檢查一般文字與姓名欄位。不是實際網站上的準確率。

## 如何再提高實際準確性

最有效的下一步是針對使用中的網站，建立「哪些欄位一定是姓名」的定位規則，再補一般文字的候選姓名。請提供不含真實姓名／證號的假資料版面或 HTML 片段。

離線命名實體辨識模型可作第二階段候選偵測，但仍需場域測試、相容性與授權檢查；不是換成 AI 就不會漏掉姓名。此版未內建任何模型。
